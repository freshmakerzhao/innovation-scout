# 实施计划、软硬件与预算口径

状态：2026-09-24 提案。工期从“方向、业务验收人、试点数据权限和环境资源均确定”的正式启动日算起；以下为 4 人左右团队的 12 周估算。

## 12 周实施表

| 周次 | 可检查的产物 | 通过后才进入下一段的条件 |
| --- | --- | --- |
| W1–W2：需求与数据验证 | 3 个监测主题、20 条真实需求或问题、50 条已知相关成果样本；来源许可清单；技术原型与模型对比记录 | 业务验收人确认范围；OpenAlex/EPO 账号与数据路径可用；定下人工审核标准 |
| W3–W4：采集与底座 | 来源适配器、游标/重试/配额、统一元数据、去重、审计字段；开发/试点环境 | 连续 7 日定时采集，失败可恢复；100 对去重样本评估；中文/英文检索基线完成 |
| W5–W6：检索与监测 | 主题订阅、每日候选队列、字段/关键词/语义检索、来源回链 | 50 条已知成果盲测；记录找回率、误报和上游延迟 |
| W7–W9：证据与机会卡 | 获授权全文解析、结构化草稿、证据引用、人工审核、需求匹配 | 抽查 30 张卡片；所有外发字段有证据与审核记录 |
| W10–W11：业务闭环 | 政策条款人工录入、派单与跟进、简报导出、权限和备份恢复 | 至少 10 张卡进入真实联系/评审；完成权限和恢复演练 |
| W12：试点评估 | 业务验收报告、误差分析、花费、运行手册、下一阶段清单 | 对照 [验收指标](01_产品范围与验收.md)由业务负责人决定扩大、修正或停止 |

排期关键依赖：真实需求和领域专家从 W1 就要参加。若数据授权晚于 W2，学位论文/本地政策等来源顺延为手工导入，试点目标以已获准数据为准。

约 **11 人月**，可由 4 位跨职能成员分担。若只有一名全职开发者，建议把首期缩为“单一来源 + 检索 + 人工机会卡”，预计 **24–32 周**，具体随数据与专家支持调整。

## 软件、账户和部署条件

- 操作系统：开发机 Windows/macOS/Linux 均可；试点服务器建议受维护的 Linux 发行版。
- 开源组件：Python 3.12、Django 5.2 LTS、DRF、PostgreSQL 17、pgvector、Redis、Celery 5.6、React/TypeScript/Vite、Docker、GROBID（需要解析时）。实施时锁定最新兼容安全补丁并核查依赖许可。
- 外部账户：OpenAlex API key、EPO OPS 注册与 OAuth 凭据；模型/嵌入服务账户由机构确定；域名、TLS 证书、邮件告警通道。Crossref 元数据可用于核对 DOI。
- 交付工具：代码托管、CI、错误监控、数据库备份、对象存储和秘密管理。生产服务与开发环境分离。

## 硬件容量建议

下表按 README 的试点数据量及约十名内部用户估算。上线前用真实文件大小、向量维度和并发重新测量。

| 环境 | 建议资源 | 用途与限制 |
| --- | --- | --- |
| 开发机 | 6 核 CPU、16 GB 内存、100 GB 可用 SSD | 可用容器运行服务和小样本数据；PDF 批处理可放测试服务器 |
| 单机演示 | 8 vCPU、32 GB 内存、500 GB SSD | 可运行数据库、Web、任务与缓存；仅用于演示或短期试点，单点故障 |
| 建议的内部试点 | 应用/任务 8 vCPU、16 GB；数据库 8 vCPU、32 GB + 300 GB SSD；对象存储 200 GB；异机备份 ≥500 GB | 服务分离、可恢复；根据 PDF 大小扩容对象存储，按月看资源曲线 |
| 私有模型扩展 | GPU 暂不采购 | 仅在数据不得送外部且选定模型、实测吞吐/显存后单独选型与报价 |

公网接入还需安全网关、防火墙、TLS、访问日志与机构安全审查；试点优先内网/专有云。对于正式多机构服务，要另做高可用、灾备、单点登录和渗透测试。

## 费用如何计算

不把动态服务单价写成固定报价。会议先确认经费上限，W2 用实际 API 响应、模型用量和云/本地报价形成采购表。

1. **人力**：约 11 人月 × 各角色实际人月成本，是主要投入。
2. **算力与存储**：上述 VM/数据库/对象存储/异机备份的月费 × 3 个月，加监控、域名和网络出口；本地服务器则算折旧、维护与供电。
3. **数据接口**：OpenAlex 免费 key 有每日 API 用量额度，超额按现行价格；EPO OPS 免费额度目前为每周 4 GB，超过后有订阅费用。授权中文资料、学位论文或商业专利库另询价。
4. **模型**：控制输入量的基线为每天筛选 50 条候选做深度分析，每条平均 4,000 输入 token、500 输出 token。按 30 天约 **600 万输入 + 75 万输出 token/月**；另算嵌入、重试和人工测试。实际费用 = 用量 × 选定供应商的当期单价。
5. **预留**：对来源额度变化、PDF 解析、模型重跑和安全整改留专项储备，由项目负责人在 W2 确定比例。

OpenAlex 当前计费与 key 使用说明见 [官方价格页](https://help.openalex.org/access/pricing/)和[认证说明](https://help.openalex.org/api/authentication/)；EPO OPS 的额度与订阅条件见[官方服务页](https://www.epo.org/en/searching-for-patents/data/web-services/ops)。采购前重新核价。

## 主要风险及应对

| 风险 | 触发信号 | 应对与负责人 |
| --- | --- | --- |
| 没有真实需求/专家 | W1 未拿到需求卡或样本 | 产品负责人推动共创；暂停匹配功能验收 |
| 数据权限、接口额度不足 | API 403/429、授权不明确 | 数据工程师记录配额，缓存和限速；改用授权导入，更新范围 |
| 中英文检索差 | W4 盲测找回率低 | 检索工程师调词表/权重/向量；仍不达标则评估独立搜索服务 |
| 模型编造或误联人名 | 卡片缺证据、专家发现错误 | 强制来源定位与人工批准；保留“未知”和纠错日志 |
| 内容敏感或不宜外发 | 企业需求含保密信息 | 权限分级、脱敏与出口审批；安全负责人审核 |
| 硬件或模型费用超限 | 月度估算超上限 | 限制深度分析候选数、批处理、缓存；重新审定采购 |
