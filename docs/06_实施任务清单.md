# 基于上游代码的实施任务

状态：2026-09-24，按 6 周内部试用拆分。已完成的事项仅为导入并固定上游源码；以下勾选项代表待实施工作。

## W1：先让底座运行

- [ ] 在 `app/` 锁定 Python、依赖、容器配置和模型服务；用现有 OpenAlex 检索运行一份真实报告。
- [ ] 记录启动命令、耗时、token/API 用量、引用原始链接、失败模式。
- [ ] 选定三个监测主题和至少各 20 条论文/专利样本。
- [ ] 核查上游根许可证和 `pyproject.toml` 的标记差异。

## W2–W3：增加持续发现

- [ ] 新建 `app/pilot_ext/`，定义来源记录、主题、运行日志和 SQLite 迁移。
- [ ] OpenAlex 日期/游标/配额适配，DOI 和来源 ID 去重；不改现有即时研究接口。
- [ ] 定时命令每日运行、幂等重试，提供“本日新增与上次相比变化”列表。
- [ ] EPO OPS OAuth、查询、XML→统一线索字段、节流与错误记录；授权 CSV/Excel 导入供联调。

## W4：形成机会卡

- [ ] 从候选线索调用现有研究代理，保存提示问题、来源和报告版本。
- [ ] 机会卡草稿字段：问题、方法、团队、使用条件、相关专利、未知项和可打开的出处。
- [ ] 人工编辑、批准和 Markdown/HTML 导出；未批准卡有明显标识。
- [ ] 准备现场演示脚本与五张专家抽查卡。

## W5–W6：让服务人员试用

- [ ] 录入 3–5 条真实需求，显示候选匹配与不匹配原因，由人确定联系动作。
- [ ] 在现有页面上增加监测结果、机会卡和需求对照入口。
- [ ] 限制内部网络访问，确认密钥和企业需求不进入 Git/外部模型。
- [ ] 连续运行 7 天，抽查来源，完成备份恢复与 1–3 人试用报告。

## W7–W8：反馈修正

- [ ] 修复阻碍实际使用的来源、引用、检索、性能和操作问题。
- [ ] 决定 V0.2 是否投入多人权限、更多来源、政策计划、专家库和正式数据库。

每个任务在代码合入时说明改动是否位于上游核心、回归了什么，以及与固定上游提交相比新增了多少维护负担。
