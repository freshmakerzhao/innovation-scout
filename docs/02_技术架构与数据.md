# 开源底座、技术架构与扩展点

状态：2026-09-24。目标是 6 周内部试用，选型以复用现成代码和控制改动面为准。

## 候选比较与决定

| 候选 | 可直接使用 | 对首版的改动 | 判断 |
| --- | --- | --- | --- |
| [GPT Researcher](https://github.com/assafelovic/gpt-researcher) | 研究代理、已有 OpenAlex 检索器、网页界面、报告、模型配置、Docker | 增加专利来源、每日监测、机会卡和需求对照 | **主底座**；上游有近期提交且核心检索器分离 |
| [PaperFlow](https://github.com/OpenRaiser/PaperFlow) | 每日论文流、反馈、精读、中文界面及本地 SQLite | 专利、企业需求、机会卡和多人部署；目前首次公开版本 0.1 | 借鉴监测体验和反馈循环，首期不整体拼接 |
| [Khoj](https://github.com/khoj-ai/khoj) | 自托管搜索、研究及定时自动化 | 同样需要专利与业务对象；AGPL-3.0 需要额外分发/网络服务义务评估 | 首期不作为底座 |
| [Open Deep Research](https://github.com/langchain-ai/open_deep_research) | 可配置深度研究代理 | 仓库在 2026-08 归档，只读 | 不用作持续开发底座 |

GitHub 提交活跃度只是维护线索。GPT Researcher 的根 [`LICENSE`](../app/LICENSE) 是 Apache-2.0，根 [`pyproject.toml`](../app/pyproject.toml) 却写 MIT；内部试验可以继续，公开分发或商用前须向上游核实并完成依赖许可证清单。保留全部原始版权与许可证文件。

## 代码组织和同步

- `app/` 是从 GPT Researcher 上游 `main` 的提交 `6f998577d547b1e54ec662dac63583aa11e3b84b` 用 Git subtree 导入的完整代码；当前尚无我们自己的功能改动。
- 后续优先把主题监测、SQLite 数据和机会卡写在 `app/pilot_ext/`，通过现有 Python API 或检索器接口调用上游能力。仅在现有接口不足时改 `app/gpt_researcher/`；每处核心改动记录原因和回归测试。
- 要更新底座时先评估上游差异与许可证，再执行 `git fetch upstream main` 和 `git subtree pull --prefix=app upstream main --squash`，在独立分支运行试用回归。不要在试用周中自动追最新版。

## 首版技术栈

| 层 | 采用现成能力 / 小扩展 | 首版不引入 |
| --- | --- | --- |
| 后端 | GPT Researcher 现有 Python 3.11+、FastAPI 服务和研究代理 | 新 Django 后端 |
| 页面 | 现有轻量页面；有需要时启用其 NextJS 页面 | 另起 React 项目 |
| 学术检索 | 已有 `OpenAlexSearch` 用于按需研究；新增带日期、稳定 ID 和配额控制的监测适配 | 自建全球论文库 |
| 专利检索 | EPO OPS 的轻量检索/转换适配；授权 CSV/Excel 用于联调 | 全量专利数据镜像 |
| 主题与审核记录 | 单机 SQLite，保存主题、来源 ID、运行日志、需求卡、机会卡与审核版本 | PostgreSQL、Redis、Celery、独立向量数据库 |
| 定时 | 操作系统 Task Scheduler/cron 调用一个幂等命令，记录成功/失败 | 分布式任务调度 |
| 模型 | 沿用 GPT Researcher 可配置的模型提供方；限定输入只含获准文本 | 首期 GPU 与私有模型 |
| 文档 | 沿用原有报告生成和导出；机会卡另导出 Markdown/HTML | 自建复杂文档服务 |

[上游检索器文档](https://github.com/assafelovic/gpt-researcher/blob/main/docs/docs/gpt-researcher/search-engines/search-engines.md)列出 `RETRIEVER=openalex` 及自定义检索器。当前 [`OpenAlexSearch`](../app/gpt_researcher/retrievers/openalex/openalex.py)每次最多取 25 条并返回标题、链接、摘要；它适合即时研究，**不足以直接承担按日期追踪、去重和团队关联**，因此这些放在小扩展中。现有 [Docker Compose](../app/docker-compose.yml)可启动后端和 NextJS 页面，但仍须配置模型及所选检索服务的密钥。

## 数据流

```mermaid
flowchart LR
    A[保存的监测主题] --> B[每日任务]
    B --> C[OpenAlex / EPO OPS / 授权导入]
    C --> D[(SQLite: 来源与去重)]
    D --> E[候选线索列表]
    E --> F[GPT Researcher 按需研究]
    F --> G[带出处的机会卡草稿]
    G --> H[人工核验并批准]
    H --> I[需求对照与联系决定]
```

### 最小记录字段

- **来源记录**：类型、OpenAlex ID/DOI 或专利公开/申请号、地域、标题、作者/发明人、机构/申请人、发表/公开日期、源 URL、获取时间、原始响应校验和。
- **主题运行**：主题 ID、查询、时间窗、来源、运行时间、成功/失败、上游配额或错误、记录数量。
- **机会卡**：来源 ID、报告及证据链接、方法与复用条件、未知项、关联需求、草稿/已批准状态、审核人、时间和版本。
- **需求卡**：问题、约束、联系人、保密级别、允许给模型使用的内容范围。

相同 DOI 或相同专利标识符自动归并；同名研究者、相似标题仅提示人工确认。模型输出是草稿，每条关键判断要保留可打开的来源链接。专利法律状态和论文的产业可实施性由专业人员核验。

## 试用运行边界

首版只供 1–3 位内部用户通过内网或 VPN 访问；如现有页面缺少所需身份认证，用网络访问控制保护，不向公网开放。密钥只放本机/服务器的环境配置，`.env`、日志、下载全文和企业需求数据不提交。定期备份 SQLite 文件及导出目录，并做一次恢复演练。需要正式多人协作、细粒度权限和高可用时，再迁移 PostgreSQL 并增加认证与审计。
