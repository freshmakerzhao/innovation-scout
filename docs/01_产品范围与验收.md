# V0.1 产品范围与验收

状态：2026-09-24 提案。首版定位为内部使用的科研情报助手；从已有开源程序扩展，先验证情报线索是否帮助服务人员工作。

## 目标用户与使用流程

1–3 位科技服务人员或领域专家设置一个产业方向、三个监测主题。系统按日获取公开论文/专利线索，并保留链接和发现时间。用户选中成果运行研究，得到带引用的简报；人工确认后形成机会卡，与 3–5 条真实企业需求对照，记录是否值得联系。

## V0.1 必须交付

| 功能 | 复用/新增 | 最小结果 |
| --- | --- | --- |
| 按需科研检索与简报 | 复用 GPT Researcher 页面、代理和导出 | 输入问题，得到论文或技术研究报告及可打开的来源 |
| 论文来源 | 复用其 OpenAlex 检索器并修正配额/元数据处理 | 按主题找新论文，保留 DOI、作者、机构、发表日期和原始链接 |
| 专利来源 | 新增 EPO OPS 轻量适配器；授权样本导入作为联调路径 | 可按主题找专利著录线索，保留公开/申请号、地域和来源链接 |
| 每日监测 | 新增简单的保存主题、定时执行、去重和运行日志 | 三个主题自动运行 7 天；失败可重试，新增线索不重复入库 |
| 机会卡 | 新增结构化草稿和人工批准 | 内容含问题、方法、条件、团队、相关专利、未知项、引用和审核人 |
| 需求对照 | 新增需求卡录入与候选对照 | 3–5 条真实需求可关联机会卡，显示匹配与不匹配理由 |

首版允许 CSV/Excel 导入需求和授权专利样本，机会卡以 Markdown/HTML 导出。用户主要使用现有研究页面和一个精简的监测/审核页面，不为首版重建完整平台。

## 明确延后的功能

大规模全量论文/专利库、中文学位论文自动采集、自动专利法律结论、政策申报资格判定、复杂知识图谱、多租户与企业端自助、完整 CRM/派单、私有模型和正式高可用。保留数据结构与原始链接，便于后续加这些功能。第 7–8 周优先修复试用中发现的阻塞问题，再定后续路线。

## 验收方式

| 项目 | 第 6 周建议标准 |
| --- | --- |
| 开源底座 | 固定的上游版本能按说明启动；至少一次真实问题运行并记录模型、来源和生成时间 |
| 监测 | 3 个主题连续 7 天执行；记录每日新增数、失败数和上游获取时间；失败能手动重试 |
| 论文/专利 | 每类准备至少 20 条可回查的真实样本；关键字段准确性由专家抽查，无法确定的信息明确空缺 |
| 简报 | 选 10 个线索生成报告；事实性主张能回到来源，错误引用和未证实判断单独登记 |
| 机会卡 | 至少 10 张由人工审核，有来源、审核人、时间、版本和“未知项”；未审核卡不能对外使用 |
| 需求对照 | 用 3–5 条真实需求完成候选排序与人工判断；业务人员指出哪些线索值得联系、哪些不适合及原因 |
| 部署 | 1–3 位内部用户按安装说明完成试用，数据备份和恢复各执行一次 |

这些是内部试用门槛，不是宣称模型或专利分析达到专业审核精度。第 1 周应确定专家样本与具体通过阈值。论文实验结果不能直接证明产业可实施；专利状态、许可和自由实施判断由相应专业人员核对。

## 后续扩展触发条件

如果试用者确实用机会卡推进团队联系，再增加账号权限、多人协作、更多来源、机构专家库和政策计划；如果主要瓶颈是检索质量，优先做标注集、中文召回和来源覆盖；如果外部模型不能处理目标数据，再评估私有模型及 GPU。
