# 产品范围与验收

状态：2026-09-24 提案；会后根据真实方向和需求卡修订。

## 目标与用户

目标是缩短“公开成果出现 → 找到相关团队和方法 → 判断是否值得接触 → 对接企业/政策项目”的时间，并保留可复核证据。首期使用者为科技服务人员、领域专家和业务负责人；企业需求方可提交需求并接收审核后的简报，默认不直接进入内部情报库。

## 首期场景

| 场景 | 输入 | 系统交付 | 人工决定 |
| --- | --- | --- | --- |
| 每日监测 | 产业主题、关键词、时间窗、关注机构 | 新增成果候选、去重记录、来源与时间 | 线索是否值得读 |
| 技术分析 | 论文/专利/合法取得的全文 | 方法、实验条件、局限、相关团队、证据片段 | “能否复用”的具体条件与未知项 |
| 需求匹配 | 企业需求卡、约束、预期成果 | 候选成果排序与逐项匹配理由 | 是否联系团队、信息可否外发 |
| 政策支持 | 人工维护的计划条款及申请条件 | 可能相关的成果、团队、缺失材料清单 | 资格与申报建议 |
| 服务跟进 | 已批准的机会卡 | 负责人、联系、反馈、下一步及状态 | 是否形成正式项目 |

## 核心对象

- **来源记录**：原始 URL/标识符、发布与获取时间、提供方、授权范围、原始元数据版本。
- **成果**：论文、专利、学位论文或其他公开资料；按 DOI、专利公开/申请号等标识符去重，保留来源映射。
- **技术方法**：问题、方法、关键参数与材料、实验或实现环境、验证结果及边界。
- **团队**：研究者、机构、关系与身份置信度；同名不直接合并。
- **需求**：应用场景、指标、约束、期限、保密级别、需求方与联系人。
- **政策计划**：原始条款、适用范围、时间、资格、主管单位及复核日期。
- **机会卡**：成果与需求的关联、证据、未知项、人工结论、负责人和外发状态。
- **服务记录**：联系、沟通、保密协议或材料请求、项目结果。

## 首期边界

1. 数据接入：OpenAlex 学术元数据、EPO OPS 专利元数据/适用字段、人工导入的授权资料；Crossref 只作 DOI 补全和核对。每个来源设配额、重试、检查点与权限说明。
2. 检索：字段过滤、关键词、语义相似与混合排序；显示匹配字段和证据，不输出没有来源的结论。
3. 分析：对可处理的摘要或全文提取结构化候选信息；模型输出始终标记为草稿，必须由人审阅才能外发。
4. 工作流：候选→已筛选→待核验→已批准→已派单→跟进中→完成/不适合；每次状态变化保留操作者和时间。
5. 用户权限：管理员、分析员、审核员、只读业务负责人；企业敏感需求仅授权成员可见。

第一版不覆盖全学科、全世界的完整全文、自动专利法律意见、自动申报或无需人工批准的对外推荐。新增来源与功能按 [会议决定记录](05_会议决定记录.md)评估。

## 验收设计

以下阈值是会议待定的**建议试点门槛**，须由真实样本基线确认后冻结。评估数据和计算脚本随实现交付，不能只看演示案例。

| 指标 | 建议门槛与测量办法 |
| --- | --- |
| 数据可追溯 | 100% 外发机会卡含原始链接、标识符、来源日期和关键判断所用证据；抽查 30 张 |
| 人工审核 | 100% 对外材料有审核人、时间及版本；检查审计日志 |
| 检索找回 | 由专家建立至少 50 条已知相关成果的盲测集；Top-20 找回率目标 ≥80%，同时报告误报 |
| 增量监测 | 对来源已经开放的记录，每天执行采集；达到来源可获取后 24 小时内入库的比例目标 ≥95%，单列上游延迟 |
| 去重 | 至少 100 对人工标注同一/不同记录；准确率目标 ≥95%，同名作者误合并单列报告 |
| 服务价值 | 至少 20 条真实需求卡或经审核的业务问题，形成 30 张机会卡，至少 10 张进入实际联系或业务评审；业务负责人评估是否可继续投入 |

## 质量判定

“能否复用”记录为分项判断：公开的实施步骤、独立复现、材料/设备/数据条件、扩展成本、适用行业、专利地域与状态、许可或合作路径。每项允许“未知”；只要关键项未知，机会卡就列出下一步核查动作。

模型质量单列测试：从不同年份、语言、来源抽样至少 100 条，评价事实支持、引用定位、漏掉的限制条件和错误关联。发现错误需能追踪输入、模型版本、提示词版本与人工修正。阈值在第 2 周由领域专家定，不凭模型自报置信度验收。
